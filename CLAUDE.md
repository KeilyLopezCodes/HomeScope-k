# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

HomeScope: a web platform for buying, selling and renting property, with a "Índice de Conveniencia" (convenience score built from nearby points of interest). University course project (UMG Jalapa, Desarrollo Web). Code, comments, identifiers, commit messages and UI text are in **Spanish**. Keep that convention.

The full design reference is `docs/HomeScope_Arquitectura.md` (C4 views, layer rules, API conventions, DB rules, ADR-01…09). Read the relevant section before making structural changes. It also says all collaboration goes through Git.

## Layout

- `homescope-api/`: Node.js (ESM, `"type": "module"`) + Express 4 + Prisma 5 + PostgreSQL 16, with Socket.io and pg-boss in the same process.
- `homescope-web/`: React 18 SPA, built with Vite 5, Tailwind 3, TanStack Query, React Router 6, React Hook Form + Zod.
- `docker-compose.yml`: local PostgreSQL on 5432 (user `admin` / `Admin123456`, db `HomeScope-k`).
- `scripts/`: raw SQL (`init.sql`, roles/permissions seed).
- `.claude/`: the "Prisma" spec-workflow agents/commands (Portuguese). "Prisma" there is the workflow name, not the ORM.


There is no linter or formatter configured in either package.

Swagger UI is at `http://localhost:3000/api/docs` (spec at `/api/docs.json`). It is generated by `swagger-jsdoc` from the `@openapi` JSDoc blocks in each `*.routes.js`, so update those blocks whenever you add or change an endpoint. `GET /health` checks the DB connection.

## Backend architecture

A modular monolith (ADR-01). Every module in `src/modules/<modulo>/` has the same files, and the layers depend on each other in one direction:

`*.routes.js` → `*.controller.js` → `*.service.js` → `*.repository.js` → Prisma

- **routes**: declare endpoints, the `authenticate` middleware and `requirePermission('<codigo>')`, plus the OpenAPI docs. All modules are mounted in `src/app.js` under `/api/v1/...`. The mount paths don't always match the module names: `identidad`→`/auth`, `geo-indice`→`/geo`, `comunicacion`→`/conversaciones`, `reputacion`→`/resenas`, `moderacion`→`/admin`.
- **controller**: parses input with the Zod schemas from `*.schemas.js` and calls the service. Each handler follows `try { … } catch (err) { next(err); }`.
- **service**: holds the business rules (ownership checks, contact-visibility rule RNF-08, and so on). It throws `AppError(code, message, status, details)` from `src/shared/errors/AppError.js`. Per the architecture doc, services should not import Express, Prisma or external SDKs. They use repositories and the ports in `src/shared/ports/` (`MapsPort`, `StoragePort`, `MailPort`, `RealtimePort`, `JobPort`), with implementations in `src/shared/adapters/`. Modules talk to each other through their service or repository, never by reading another module's tables directly.
- **repository**: the only layer that uses Prisma (`src/config/prisma.js`). It defines explicit `select` objects so that fields like `password_hash` are never exposed.
- `src/shared/middleware/errorHandler.js` turns `ZodError` into a 400 `VALIDATION_ERROR` and everything else into the single error format `{ error: { code, message, details } }`. The frontend client depends on this shape.

**Auth (ADR-04):** a short-lived JWT access token (15m) is sent as `Authorization: Bearer`. The rotating refresh token lives in an `httpOnly` cookie scoped to `path: /api/v1/auth`. The token payload carries both `roles` (array) and a legacy singular `rol`, and `authenticate` normalizes old tokens. Authorization is RBAC: `requirePermission(codigo)` looks up which roles hold the permission in the DB (`Permiso`/`RolPermiso`/`UsuarioRol`). If the permission code is not registered, the request is allowed through.

**Database:** `prisma/schema.prisma` is the source of truth. Model fields and relations use `snake_case` (`password_hash`, `usuario_rol`), and the API currently returns those names as they are. Enum-like columns are `VARCHAR` + `CHECK` (ADR-09), not native enums. Constraints Prisma can't express (partial unique indexes, CHECKs, Spanish full-text with `f_unaccent`, extensions) are hand-added as SQL inside the migration files. Text/map searches must use parameterized `prisma.$queryRaw`.

**File storage (strategy pattern):** `src/shared/adapters/storage/index.js` exports `storage`, chosen by `STORAGE_DRIVER` (`local` writes to `UPLOADS_DIR`, which `app.js` serves at `/uploads`; `cloudinary` is a stub to implement). Every strategy implements `StoragePort` (`subir(archivo, carpeta)` → `{ url, public_id }`, `eliminar(publicId)`). Multipart uploads go through `shared/middleware/upload.js` (multer in memory, checks type, size and count). Photo limits are in `FOTOS_CONFIG` (`propiedades.schemas.js`), and the frontend repeats them in `features/propiedades/services/fotosService.js`.

**Not yet implemented (TODOs):** Socket.io auth and per-user rooms (`src/server.js`), pg-boss startup and workers (`src/jobs/index.js`), and most of the ports/adapters. Several modules still return `501 Not implemented`.

## Frontend architecture

- `src/main.jsx` wraps the app in `QueryClientProvider` and `BrowserRouter`. `src/app/App.jsx` holds all routes, a `ProtectedRoute` (redirects to `/login`, or to `/403` when the role doesn't match `user.rol`), and `MainLayout` from `src/shared/components/`. Routes for features that aren't built yet render `ComingSoonPage`.
- `src/features/<feature>/` mirrors the backend modules. Each feature exposes its pages and hooks through an `index.js` barrel, and `App.jsx` imports from those barrels.
- `src/shared/api/client.js` (`apiClient(path, options)`): keeps the access token **in memory only**, sends `credentials: 'include'`, retries once after `POST /api/v1/auth/refresh` on a 401, and throws an `Error` that carries `code`, `details` and `status` taken from the backend error shape.
- `src/features/auth/authContext.jsx`: on mount it restores the session through the refresh cookie, then fetches `/api/v1/auth/perfil`. It caches a minimal user `{ id, nombre, email, rol }` in `sessionStorage` (never the token). It exposes `signIn`, `signOut`, `updateUser` via `useAuth()`.
- Role names are not fully settled: routes check several spellings (`vendedor`/`seller`, `admin`/`administrador`) case-insensitively.
